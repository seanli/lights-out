# Decisions

| # | Decision | Kind | Why |
|---|---|---|---|
| 1 | Level path: 50 numbered levels in named chapters, 1–3 stars by moves vs par, progress saved | decided with the user | Clear sense of progress for a casual phone game |
| 2 | One-tap hint highlights one correct cell; each hint costs 1★ (min 1★) | decided with the user | Unsticks players without giving the puzzle away |
| 3 | Classic 5×5 only at launch; sizes/variants later as modules | decided with the user | Keeps the first version focused |
| 4 | Must be playable offline | decided with the user | User request at approval |
| 5 | Vite 8.3 + TypeScript 7.0 + Vitest 5.0 + Valibot 1.5, single-file build (vite-plugin-singlefile 2.3.4) | lead default | Current, verified building here; single file fits the artifact host and offline use |
| 6 | Solver written in-house (GF(2) elimination, ~60 lines) | lead default | No maintained library exists; the maths is small and standard |
| 7 | Hint penalty survives Restart and reload until the level is solved | lead default | Otherwise Restart is a free way to erase the cost |
| 8 | Undo takes back a tap and doesn't count as a move; hints can't be undone | lead default | Mis-taps on a phone shouldn't cost stars |
| 9 | Levels unlock one at a time | lead default | Simple, matches the level path |
| 10 | Dark-room look only, no light theme | lead default | The glow is the game; the mockup was approved |
| 11 | Solve plays a ~0.8s sweep, then the sheet; taps during the sweep are ignored | lead default | Celebrates the win without blocking normal play |
| 12 | Debug console behind `#debug` (not `?debug`) | changed after evidence | The artifact frame passes only a plain hash, never a query string |
| 13 | Offline: zero network requests (fonts bundled via @fontsource), standalone HTML file, plus a PWA build with a hand-written service worker | lead default | Artifact pages can't register service workers; the PWA is the only way to open with no connection on a phone. The app is one file, so a 30-line worker beats Workbox |
| 14 | Hints used are counted by `progress` (from `hints:shown`), not read from the hints slice at solve time | lead default | Keeps handlers order-independent |
| 15 | Levels come from a fixed seed (rules.json → levels.seed): every player gets the same 50 boards | lead default | Stars are comparable between players; tuning is reproducible |
| 16 | Sound on by default; a synthesised wall switch chosen by the owner in a sound lab (on brighter than off, neighbour ticks following the ripple, six takes with small variation), relays and a warm swell on solve (fuller on a boss), glass ticks for stars and hints; mute remembered | decided with the user (was: pentatonic blips) | Owner asked for a satisfying, ASMR-like switch that isn't annoying and picked "Wall switch" of three candidates |
| 17 | The progress slice carries the star rule (`scoring`) so views show tiers without owning the rule | lead default | One source of truth for the star thresholds |
| 18 | Offline version hosted on GitHub Pages (seanli/lights-out), deployed by Actions on push | decided with the user | User created the repo |
| 19 | Learn screen with 5 interactive lessons (shapes, order, chasing, bottom-row table, shortest solution) plus practice with optional assist; opened from home and the level header; back resumes the board untouched; practice never affects stars | decided with the user (form: lead default) | User asked for a place to learn pattern recognition; the bottom-row table and quiet patterns are computed from the solver so they can't be wrong |
| 20 | Page-weight target retuned from ≤150KB raw to ≤200KB raw and ≤80KB gzip | changed after evidence | The Learn screen (user request) and full copy pushed the single file to ~151KB before the last views; gzip (what actually loads) is ~63KB and boot stays well under the 800ms target. Fonts were already subset 45→26KB |
| 21 | Bottom-row table and quiet patterns are computed from the solver at startup, not written in data | lead default | They can never disagree with the game's rules |
| 22 | Tap-response target measured from the game's first pointerdown listener (≤ 8ms to the light change, ≤ 25ms to the next frame) instead of from the touch's timestamp | changed after evidence | In headless Chromium ~15–20ms passes between the touch timestamp and any page code; the game's own work is ~6ms p95 including the first tap that starts audio |
| 23 | Phone/browser Back follows the screens (home ← play ← learn) via history entries; skipped when #debug owns the hash | changed after evidence | Play-test: Back left the game on Android |
| 24 | In-game Patterns panel on the play screen (board stays playable): chase line, live advice, live bottom row, the 7-row table with the matching row lit; never marks the main board | decided with the user (form: lead default) | User wants the patterns visible during a game; Hint stays the only paid on-board help, and the method rarely reaches par so stars still reward the short way |
| 25 | Page-weight target retuned again to ≤230KB raw / ≤90KB gzip | changed after evidence | The Patterns panel (user request) took the page to 202KB / 77KB gzip. Measured: Learn adds 31KB, the debug console 21KB; boot stays ~120ms, so weight isn't hurting play |
| 26 | Audio starts right after the tap that opens a level, not on the first board tap | changed after evidence | Probe: the first winning tap of a session took 27–42ms because creating the audio context is slow; now every tap, winning ones included, handles in ≤ 5ms |
| 27 | The solve sweep starts on the next frame | changed after evidence | Reading tokens and forcing layout inside the winning tap delayed the last light's change |
| 28 | Replay reproduces state and timestamps from the snapshot and input log; storage read at init (tutorial's finished levels, sound setting) is not recorded | lead default | Replay is a debugging aid; recording storage too would double the session size for little gain. Revisit if a bug needs it |
| 29 | Progress merges with whatever is stored before every write (most stars, fewest moves); reset is the only replace, and keeps a `.before-reset` copy | changed after evidence | Code review: two open tabs could overwrite each other and lower stars |
| 30 | Older iOS Safari: shell polyfills structuredClone and Array.at; CSS falls back to viewport sizing without container queries | changed after evidence | Code review: iOS < 15.4 couldn't boot, < 16 would collapse the board |
| 31 | Variety: rooms 4×4, 6×6, 7×7, Cross, Ring, Diamond (shapes on a 7×7 grid with gaps), 12 levels each, in a separate Variety menu that opens after classic level 20 (level 10 since 57); rooms all open, levels inside a room unlock one at a time | decided with the user (details: lead default) | User picked sizes + shaped boards, a separate menu, and no extra rules; wrap-around and diagonal taps were offered and not chosen |
| 32 | Room level ids are fixed numeric ranges (idBase + index, e.g. 4×4 = 1001–1012); the save shape stays v1 | lead default | Saves are keyed by level id; numeric ranges need no migration and never collide with classic 1–50 |
| 33 | A press never reaches across a gap; gaps are not buttons | lead default | Same rule everywhere: "a tap flips the light and its neighbours" — a gap has no light |
| 34 | Patterns panel and Learn stay about classic 5×5; on other boards the panel shows only chase advice | lead default | The bottom-row table has 63–127 rows on 6×6/7×7 and doesn't apply to shaped boards |
| 35 | Polish direction (design-lead spec): a dark room, a warm board, nothing else asking for attention; same-frame tap with bloom/afterglow and a 24ms neighbour ripple; quiet chrome (moves, the star tier you're on, tools under the thumb); progress as a house lighting up | lead default | Owner asked for "The Good Sudoku quality" |
| 36 | Header "Up to ★★★" removed; a "−1★ hint" chip joins the tier row | lead default | It duplicated the tier chip and collided at 320px |
| 37 | Win sweep is a warm wash through a dark board (timing unchanged); the sheet opens at 640ms instead of 800 so its slide overlaps the sweep's tail (changes #11's number) | lead default | The old sweep looked like a new puzzle lighting up; the win felt long at ~1.9s |
| 38 | Haptics live in the sound module (vibrate where supported, silent on iOS), on the same on/off switch | lead default | One module owns device feedback; no contract change |
| 39 | Info and warning notices show on home, Variety and Learn but not on the play screen (errors show everywhere) | lead default | A persistent warning took ~60px off the board on small phones; the player sees it before they start |
| 40 | A board cell's touch target is its whole grid slot (taps in the gutter press the nearest real cell); probe checks slots, not painted tiles | lead default | Keeps 7×7 tappable on phones without shrinking the chrome; the painted tile can stay smaller for the look |
| 41 | Page-weight target retuned to ≤280KB raw / ≤105KB gzip | changed after evidence | Combined polish + Variety build is 254KB / 94KB gzip. Measured shares: Learn 44KB (lessons, echoes, drill), console 21KB, play-view 19KB, home 16KB, Variety 9KB, CSS 61KB, fonts 34KB. Boot is 164ms against an 800ms target, so weight isn't hurting play; trimming CSS duplication is a follow-up |
| 42 | Home is one menu like The Good Sudoku: Continue on top, then every board as its own row (Classic, 4×4, 6×6, 7×7, Cross, Ring, Diamond), then Learn. A row opens that board's level screen (the `variety` module now shows any pack, classic chapters included). Rooms still open after classic level 20 (level 10 since 57) and show that as a quiet line on their row; Continue follows the board last played (progress now records room levels as `lastLevel`) | decided with the user (layout: lead default) | User asked for each variety as its own item on the same menu (replaces #31's separate Variety menu) and confirmed the level-20 gate; a new player meets the tutorial first |
| 43 | Every room gets a short guide in Learn (`guide-<room id>`), linked from its board screen and the Patterns panel. Full rectangles teach chase + a per-light rule: 4×4 chasing always clears; 6×6 "tap the top lights two to each side (A and F also themselves)"; 7×7 "the three above it". Shaped rooms teach tap shapes (plus/T/L/pair where edges and holes cut it) and chasing with the panel looking up the top-edge fix | decided with the user (content: lead default) | User asked for per-variety guides, especially bottom-row recognition. Measured: on Cross/Ring/Diamond one leftover light needs 10–21 taps to clear, so no memorisable table exists there; the panel computes it instead. Replaces #34 |
| 44 | Back walks the trail of screens (menu → board → level → Learn and back again); the play screen's Back returns to where the level was opened from | changed after evidence | Integration play-through: after a trip to a guide from the Patterns panel, Back from a Ring level skipped its board and landed on the menu. Extends #23 |
| 45 | Boards: Classic 5×5 (50 levels), Tall room 5×6 (40), Wide room 6×6 (40), Great hall 7×7 (30), Cross/Ring/Diamond (30 each), and Extreme: Ballroom 8×8, Cathedral 10×10, Tower 5×16 (30 each). 4×4 dropped; the Spire 6×18 offered and dropped. Menu in three sections (Boards, Shapes, Extreme) | decided with the user (counts and names: lead default) | Measured per size (20,000 random boards each): 4×4 tops out at 7 taps, too shallow for bosses; 5×6's fix rule is the simplest (tap straight above); 8×8+ squares fall under 44px, so 10×10 needs aim-and-release; the Tower scrolls; 9×9 and 11×11 were rejected (chasing nearly always clears 9×9; 11×11 has 31 leftover patterns). Counts stop where a boss can no longer be clearly harder |
| 46 | Levels come in bands of ten in data (`{ pars: [9], boss }`): nine that ramp, then a boss drawn with a skull, at least 1.5× the band's hardest level (tested). Normal levels top out near a board's median difficulty; bosses carry the extremes (Classic 50 = par 15, the hardest 5×5 board) | decided with the user (curves: lead default) | Owner asked for a boss every 10 levels, "drastically harder at that band", and balanced difficulty. All boards were regenerated: saved stars stay on the same level numbers |
| 47 | Home shows the release version at the bottom (`package.json` version via `env.version`; every release bumps it) | decided with the user | Owner wants to see which build is the latest |
| 48 | Board slots under 40px switch to aim-and-release (press-and-hold shows a magnifying bubble, slide, lift to press); a tall board scrolls and presses on release so a swipe never presses; everything else keeps the instant press on pointerdown | lead default | 10×10 has 34–36px slots on phones; 7-wide boards at 320 (41px) and 8×8 at 375 (42px) sit just under 44px, which decision 40 already accepts for whole-slot targets, so they keep the instant feel |
| 49 | Page-weight target retuned to ≤310KB raw / ≤112KB gzip | changed after evidence | Three new boards, bosses, the aim helper and four more guides took the build past 280KB (about 286KB before the guides and the new sound). Boot stays 185–325ms against the 800ms target, so weight isn't hurting play; trimming CSS duplication remains the follow-up |
| 50 | The Tower is 6×16 (was 5×16; 8×16 since 62): same "tap straight above" rule, 57px cells at 390 wide | decided with the user | Owner asked for a 6-wide tower; 6×16 is one of the heights where the bottom-row fix is still "straight above" (measured), so its guide is unchanged |
| 51 | One layout rhythm: shared screen header, bottom bar, menu rows and sections; side gutter grows a little on bigger phones; the play screen keeps one anatomy with Patterns open or closed (the panel only slots in above the bar; nothing changes form); the app is fixed to the viewport so it fills the screen inside the artifact frame | decided with the user (system: lead default) | Owner found layout tight and inconsistent, especially the game view when Patterns toggles, and that the game wasn't full screen vertically (the host pads :root by the safe areas: 78px lost on a notched phone) |
| 52 | Lessons and guides follow a first-time-player review: board-first rule steps with a letter picker (the lights step became strips in 71), counts instead of "All dark." when lights remain, phase-aware coaching in practice, practice boards whose first chase is short, one shared vocabulary ("two places left and right", "top-edge light") | decided with the user (content: review + lead) | Owner asked to improve the guides and lessons; an independent review found demos below the fold, wrong captions, untaught practice and 27–79-tap Assist grinds |
| 53 | Play screen on tall phones: the status row sits right above the board and the pair is centred between the header and the bar (spare height splits above and below); the Patterns panel shows only what is relevant now on every board (classic: your row and its top taps; the 7-row table moved out of the panel into lesson 4), so opening it moves the board up into the spare space and shrinks it only on short phones; the header starts 1.4× the top safe area down on notched phones (iOS dims what sits right under the status bar) | decided with the user | Owner, on a phone: "so much wasted space at the top"; the panel "shrunk the top game board, there's definitely a more elegant approach"; "always only show the current relevant option like the variant boards". Measured at 430×932: the board keeps its full 390px with the panel open (was 270) |
| 54 | A board that scrolls (the Tower) fades its edge wherever more rows are hidden: bottom only at the top, both in the middle, top only at the bottom (`data-more-above` / `data-more-below`, CSS mask, 48px) | decided with the user | Owner: "for scrollable boards like the tower, make the bottom/top look more scrollable when I can". A fade says "more this way" without an extra control, and goes away at the end so it never lies |
| 55 | The lineup: Boards (Classic, Great hall 7×7, Ring, Diamond), Twists (Stuck 6×6, Hex, Cube, Wired 5×5), Extreme (8×8, named Cathedral since 62; the Tower, 8×16 since 62), then Custom. Retired: Tall 5×6, Wide 6×6, Cross, Cathedral 10×10; their level ids stay reserved, so a save keeps their stars | decided with the user | Owner: drop what's too similar, boring or less challenging. Measured: Tall's fix is "straight above" (as the Tower's); Cross and Ring stall the chase once (4 and 3 lights, 4 solutions each) while Diamond stalls on three rows (1 solution); 9×9 has 256 solutions and the chase nearly finishes itself; Cathedral needs the magnifier on every phone and is the same ~100-light grind as the Tower; 8×8 is the biggest square tapped directly (39–44px). Custom can make any dropped rectangle |
| 56 | Room levels tangle their presses: each press lands within two steps of another (clusters of three or more), and no press of the fewest solution may show as its whole footprint; openings start harder; every boss stays ≥ 1.5× its band (decision 44). Classic is unchanged (pinned) | decided with the user | Owner: bigger boards "start too easy, I can easily tell which crosses to click". Measured 40–58% of presses readable as a whole cross before; 0% now, every par exact (lib/puzzle.ts, levels.test.ts) |
| 57 | The other boards, and Custom, open after classic level 10 (the first boss), not 20 | decided with the user | Owner asked for 10 |
| 58 | The Cube: 3×3 lights a face, every light touching four (round the edges too), so there is no bottom row to chase into. Shown tilted so the front, top and right faces show; a swipe (or Shift + an arrow) turns it a quarter, the cube following the finger; taps press on release and only the faces toward you take them; a line counts lit lights out of sight; a hint or keyboard focus on a hidden light turns its face to the front. 64 solutions a puzzle: par is the shortest | decided with the user (interaction: lead) | Owner: "What about a 3D cube mode too!?" CSS 3D (no library); the faces' frames in lib/cube.ts decide both which lights touch and how the net folds, so the two can't disagree. Probe: 27/27 visible taps land, a swipe never presses |
| 59 | Hex is a honeycomb (a hexagon of side 4, 37 lights): hexagon tiles with a thin seam, centred on the board (amended in 66; first shipped as round lights). A tap goes to the nearest tile centre, which is exactly the hexagon under the finger. Its touch slot (the pitch) is ≥ 40px from 375 wide; at 320 it is 37px, and the rule bends to 35 there (as for the Tower, decision 62) rather than add a magnifier to a seven-across board | decided with the user (rule bent: lead) | Seven and a half lights must fit across. Probe target 15 checks it |
| 60 | Stuck and Wired: each level carries its own stuck cells or wiring in its shape. A stuck switch is a light you can't press: a tap shakes it and costs no move (board:refused 'stuck'); stuck cells sit apart, off the edge. Wiring comes from a named palette (lines, the plus, the cross, T's, corners), a few patterns a level, gentle ones first; the cell draws a spoke toward each light it also flips | decided with the user | Owner liked wired switches, hex and stuck cells. The solver now handles one-way presses and cells that can't be pressed (brute-force checked) |
| 61 | Custom: pick the grid (square up to 10×16, hex side 3–5, cube 3–4), a twist (none, stuck, wired on squares), a difficulty (par as a share of the lights, rules.json → custom); settings are remembered; puzzles are tangled like the rooms and made with the session RNG; never saved (progress scores the stars in memory). After a solve: New puzzle, Replay, Change board | decided with the user | Owner: "a game mode where I can customize a board myself based on my preferences". It also brings back any retired rectangle on demand |
| 62 | The Tower is 8×16 and the 8×8 is named Cathedral (the 10×10 Cathedral retired in 55; its ids stay reserved) | decided with the user | Owner: "Would tower at 8 width be the hardest? If so pick it", "rename 8 to Cathedral". Measured on 16 rows: top taps per bottom light 1 each at 5 and 6 wide, 15 in all at 7, 20 at 8 (2, 4, 3, 1, 1, 3, 4, 2: mirror-symmetric); 9 wide falls under the 40px slot even at 390. 8 wide gives 41–49px slots from 360 to 430 and 35 at 320, where the rule bends to 35 as for the honeycomb (a scrolling board can't use the magnifier). Pars raised for 128 lights |
| 63 | Custom squares run from 3 × 3 to 20 × 30 (MAX_COLS 20, MAX_ROWS 30). A tall board scrolls only up to 8 across; wider ones fit the screen and use the magnifier, and the screen says so for big boards. Holding − or + keeps stepping. A puzzle asks for at most 80 presses (rules.json → custom.maxPar). On the few sizes with a huge null space (19 × 19 has 2^16 solutions) the par is a short solution, not always the shortest | decided with the user (limits: lead) | Owner: "pick any number width and height, maybe 20 or 30 max", "size 3 minimum too". Past 20 across a light is under 16px on a phone, too small even to aim at. Solver: 40ms to set up a 20 × 30 board, under 1ms a solve |
| 64 | Page-weight target retuned to ≤ 365KB raw / ≤ 130KB gzip | changed after evidence | Four boards, a 3D cube, Custom mode and four guides took the build to 353KB / 126KB (from 305KB / 109KB). | 65 | Lessons use the shortest fix in all: the bottom-row table and the fixer pick the top taps with the fewest taps counting the chase after them (ties: fewer top taps), so B D is fixed by A B C. | 66 | Twist looks: Hex tiles are hexagons set like a honeycomb (the glow is a drop shadow on the shape); a Wired switch draws circuit traces from a hub to a pad at each edge it wires; a Stuck switch is a riveted plate with hazard stripes. | 67 | A boss tile in the level list wears its skull as a small round badge in the top-right corner, out of the flow: every tile's number and stars sit in the same place | decided with the user | Owner: the skull above the number broke the grid's clean centre alignment |
| 68 | The Patterns panel answers every bottom row a chase can leave, not only rows built from lone lights.
